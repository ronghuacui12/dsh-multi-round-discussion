# 结构化输出容错 · 实现说明

日期：2026-10-17 · 对应现象：`运行失败：JSON is malformed: got "]" while "{" was open.`

## 现象

一次真实研讨 `mmd-4ebdba3a`：两个模型已各自出完方案、4 条互评、主导也已完成决策，随后整条 run 直接判为 `failed`，notice 只有一行：

```
运行失败：JSON is malformed: got "]" while "{" was open.
```

也就是说：前面所有产出（提案 / 互评 / 决策）都白做了，只因为计划阶段有一份 JSON 有个括号写错。

## 三层原因

1. **括号错型时立刻抛错，修复逻辑根本没机会跑。** `extractJsonValue` 一边扫描一边只看括号**类型**，遇到 `]` 而栈顶是 `{` 就抛 `JSON is malformed`；而上一版加的 `repairJsonText` 只在"括号平衡但 `JSON.parse` 失败"时才调用 —— 这条错误路径提前返回了。
2. **决策 / 计划解析失败没有重试。** `LeadModel.decide()` / `buildPlan()` 解析失败就把异常抛到 run 层，run 直接失败。
3. **没有兜底。** 即使两次都失败，也没有"降级继续"的路径。

## 改动

| 文件 | 改动 |
|---|---|
| `plugin/lib/utils/json.js` | `extractJsonValue` 重写：括号**类型不匹配就地修复**（`]` 关闭 `{` 时改写为 `}`）、多余右括号丢弃、未闭合时自动补右括号；被 token 上限截断时先闭合字符串再补括号，然后尝试 `JSON.parse` → `repairJsonText` → 再解析。新增内部 `tryParseJsonSpan()` / `describeJsonFailure()` |
| `plugin/lib/plugins/lead-model.js` | 新增 `STRUCTURED_REPAIR_HINT`；`decide()` 与 `buildPlan()` 解析失败后**重试一次**（把"上次输出不是合法 JSON"回传给模型，要求只输出一个 JSON 对象） |
| `plugin/lib/plugins/orchestrator.js` | 新增 `fallbackDecision()`：决策两次都解析失败时按**置信度最高的方案**生成决策并提示降级；`runPlanning()` 计划两次都失败时降级为**单步文字方案**（`mutatesState: false`，不调用任何工具），run 继续走完并把结果交给最终答复 |
| `plugin/lib/plugins/orchestrator.d.ts` | 补 `private fallbackDecision;` 声明 |
| `build/structured-json-smoke.mjs` | 新增 17 项断言 |

## 现在的行为

- 括号写错、缺逗号、字符串里裸引号、尾逗号、`True/False/None`、被截断 —— **都能救回来**。
- 救不回来时：先重试一次；再不行，决策按置信度兜底、计划降级为文字方案，**run 不再整条失败**，并且在 notices 里明确写出降级原因。

## 边界

- 修复是**保守**的：只在 `JSON.parse` 失败后启用，不会把合法 JSON 改坏；实在修不好仍然报可读错误并走降级路径。
- 降级方案不会伪造执行：`mutatesState: false`、不调用工具，最终答复里会说明"计划生成失败"。
- 需完整重启 DSH 后生效（宿主缓存 ESM 模块）。

## 补充（2026-10-17 · 评审阶段那条同样的错误）

现场又出现了一次同族错误：`评审者 … 失败：Found a balanced JSON span but it does not parse: Expected ',' or '}' after property value in JSON at position 34`。评审失败不会拖垮 run（只会少一位评审者的意见），但说明修复还不完整。补了三处：

| 位置 | 补充 |
|---|---|
| `plugin/lib/utils/json.js` | 括号平衡但解析失败时，`repairJsonText` 现在还会把**全角标点**当结构字符处理：`，`/`、` → `,`、`：` → `:`、中文引号 `“ ”` 作字符串分隔符（仅在结构性位置收尾，正文里的引号保持原样）；引号收尾的判定也接受全角结构字符 |
| `plugin/lib/plugins/discussion-engine.js` | `reviewOne()` 解析失败**重试一次**（附 JSON 修复提示），避免直接丢掉这位评审者 |
| `build/structured-json-smoke.mjs` | 扩到 **23 项**：全角逗号 / 全角冒号 / 中文引号 / 数组缺逗号 / 评审样例 / 属性间缺逗号 |

另外提醒：若设置页的「工具级二次确认」被勾上，执行器会**跳过**所有写工具并记为 skipped（这是它的字面语义）。本次已通过设置接口把它关掉（`toolConfirmation: false`），无需重启即生效。
