## 三、和交付包原方案的两处关键偏离（重要）

交付包 p3 的写法是「host 平面那行 disabled，引擎只活在 preset 里」。**实测这条在本机行不通**：

1. 把 host 平面那行 disabled 之后，插件**不再进入客户端 boot graph**
   （`window.__DSH_BOOT__` 里找不到 `dsh-multi-model-discussion`）→ 设置页和讨论标签页都不会出现。
   交付包注释里「disabled 只关引擎行，不影响客户端分发」在本机 0.2.0-rc.2 上**不成立**。
2. 反过来把插件同时挂在 host 平面和 preset 里，会因为**同一个包名被两个 Loader 条目解析**而被
   客户端模块系统拒绝，客户端 bundle 依然不出现。

所以最终采用：**插件本体只挂 host 平面**（客户端 UI + HTTP 接口 + 设置页 + `multi_model_discuss` 工具），
preset 只提供 persona 与随行技能。

配套的一个必需补充：执行模型是「按当前作用域枚举工具」的，而工具行在 DSH 里默认只声明在 preset 内部，
引擎在 host 平面看不到它们。因此把 `read/write/edit/glob/grep/pwsh` 也注册到了 host 平面——
否则执行模型永远拿不到任何工具，计划只能变成一段说明文字（这一点在改造前实测复现过）。

## 四、怎么用

1. **重启一次桌面端**（或在当前页面按 Ctrl+R 刷新）。客户端 bundle 是在页面加载时进 boot graph 的，
   刷新后才会出现「研讨模式」设置页和「多模型研讨」标签页。
2. 打开「设置 → 研讨模式」，给三类座位选模型（host 已有的路由都在下拉里），需要的话点头像换图片，保存。
3. 在任意会话里点顶部标签环的「**多模型研讨**」，在输入框里提问题，点「发起研讨」。
4. 想进入预设：新会话时选「**研讨模式**」（设置 → Agent 预设 里可见）。
