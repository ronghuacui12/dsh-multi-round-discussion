# 工具自举：缺什么就自己装

日期：2026-10-17 · 对应现象：「9 步全 failed，因为机器上没装 playwright / 没起 mailpit / 没 HAR」

## 背景

执行器过去被两条硬约束卡住：

1. **计划阶段假设环境已就绪**：计划里不会安排“装依赖 / 起服务”的步骤，所以一旦缺东西，后面每一步都只能报失败。
2. **执行器不得增删步骤**：即使它发现某个命令不存在、某个模块没装，也只能如实记录 failed，不能自己装。

同时执行器其实**早就有能力装**：它有 pwsh、有 npm/npx、有 python -m pip、能下载文件。缺的只是“被允许 + 被要求”这么做。

## 改动（只改提示词，不动引擎）

| 位置 | 改动 |
|---|---|
| plugin/lib/core/prompts.js 的 PLAN_SYSTEM | 计划阶段新增硬要求：**不要假设工具已装**；凡是依赖命令/包/服务的步骤，必须先在计划里安排「环境准备」步骤（pwsh 检查 → 安装或启动 → 再检查验证）；安装类步骤要写 acceptance（退出码 0 且检查命令符合预期）；步骤上限从 10 放宽到 12 |
| plugin/lib/core/prompts.js 的 buildExecutorSystem() | 执行阶段新增：**缺依赖先自己修**（pip/npm/下载/起本地服务），装好重试该步骤；只有安装也失败才记 failed，并在汇报里写清装了什么、卡在哪；安装不算“计划外新增步骤”。另加国内镜像提示 |
| 镜像 | pip -i https://pypi.tuna.tsinghua.edu.cn/simple；npm --registry=https://registry.npmmirror.com；playwright 浏览器 PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright |

## 仍然建议

- 需求里写明「工作区 = D:/1」和目标域名，缺 HAR/schema 时让它停下来问，而不是编造 URL。
- 不要在计划里用 todo_write（执行器无 agent 会话，必然失败）。
- 安装类步骤会真的联网下载，注意时间与磁盘。
