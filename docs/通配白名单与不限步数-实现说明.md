# 通配白名单与不限步数 · 实现说明

日期：2026-10-17 · 对应提交主题：`feat: 执行模型通配白名单（*）与不限步数（0）`

## 背景

上一版已经把「工具级二次确认」和「计划审批」解耦（`83995b9`）：`execution.toolConfirmation` 默认关，`write/edit/pwsh` 不会再因为"没有确认通道"被整片跳过。

还剩两个让执行模型"用不满"的限制：

1. **白名单是快照**：`execution.allowedTools` 逐条列名字，之后新挂的工具（比如再加一个 MCP 服务器）不会自动允许，得回设置页重新勾一遍。
2. **步数上限**：`execution.maxSteps` 是单次执行里工具调用的轮数上限（默认 12），用光就停。

## 改动

| 文件 | 改动 |
|---|---|
| `plugin/lib/core/sandbox.js` | 新增 `ALL_TOOLS = '*'`：白名单含 `*` 时 **所有工具都允许，包括之后注册的**；`maxSteps` 为 `0 / undefined / 负数` 时解析为 `Infinity`（不限轮数，仍受预算与中止信号约束）；新增 `allows()`，`visibleTools()` / `decide()` 统一走它 |
| `plugin/lib/host/user-settings.js` | `normalizeExecution` 允许 `maxSteps: 0`（原先要求正数会直接报错） |
| `plugin/lib/core/prompts.js` | 无限轮数时系统提示词改为「本轮没有轮数上限：按需要调用工具，直到计划完成」，不再把 `Infinity` 打给模型 |
| `plugin/client-src/settings.tsx` | 工具白名单新增「全部（含以后新增）」预设（写 `*`）与「只选目录里的」；命中通配时显示「✓ 全部工具（*）」并可一键撤销；步数输入允许 0 并提示「0 = 不限」 |
| `plugin/lib/client.js` | 重新构建（仍是 `window.__ModuleLoader__.load(...)` 信封，仅 React 外部依赖） |
| `config-root/roster.json` | 模板改为 `{"mode":"confirm","permissions":"full","allowedTools":["*"],"maxSteps":0}` |

## 现在的语义

- `allowedTools: ["*"]` → 宿主当前暴露的**全部**工具，且以后新增的自动包含。
- `maxSteps: 0` → 单次执行**不限轮数**；每轮模型可一次发起多个工具调用，所以实际调用次数没有上限。
- 仍然保留的安全阀：计划审批（`mode: confirm`）、预算（token / 成本 / 时长 / 讨论轮次）、中止信号、工具级二次确认（`toolConfirmation`，默认关）。

## 配置示例

```json
"execution": { "mode": "confirm", "permissions": "full", "allowedTools": ["*"], "maxSteps": 0 }
```

## 验证

- `node build/sandbox-permission-test.mjs` —— 10/10：通配符可见全部工具、含未来新增、写工具放行、`maxSteps=0` 解析为不限、白名单外仍拒绝、有限步数保持原值、开启 `toolConfirmation` 时行为不变。
- `node build/ui-smoke.mjs` 34/34、`node build/table-smoke.mjs` 24/24。
- 宿主改动 `node --check` 全部通过。

## 边界

- `*` 只是"允许"，不改变 DSH 的沙箱：真正让工具不受限的是 `execution.permissions: "full"` + 部署默认 `sandbox-policy.mode: danger-full-access`。
- 不限轮数不等于不限成本：预算守卫仍会在 token / 成本 / 时长超限时终止整次研讨。
- 需完整重启 DSH 后生效（宿主缓存 ESM 模块）。
