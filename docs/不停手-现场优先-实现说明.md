# 不停手 · 现场优先（为什么它老在停、在问）

日期：2026-10-17 · 触发：用户「怎么样才能不让他报错，让我一劳永逸，别再每次在问了，给他安装一切的权限」

## 真实根因：不是权限，是它不认识现场

上一轮研讨的计划里出现了 `ep_book_workspace/`、`har/contract.har`、`schema/*.json`、`sessions/archive/` —— **这些路径是模型凭空发明的**。而工作区 `D:/1` 里真正存在的是：

- `D:/1/pachong/CONTRACT.md` —— 邮箱服务（`127.0.0.1:8787/api/mailboxes`，tag `ep{NNN}`）、话数清单、点数预算 101pt
- `D:/1/pachong/bundle/next_steps.md` —— 真跑前必须补的 4 件事（PowerShell 7.4、5 个 unit 脚本、price 字段、闭环产物）
- `D:/1/pachong/fixture/mock_mailpit.py` / `mock_site.py` —— 项目自带的本地 mock（8787 / 8790）
- `D:/1/pachong/fixtures/env_check.json` —— `kurage_reachable: true`、`playwright_ok: true`

也就是说：**执行器一直在按一份虚构的地图找路**。它没错，是计划离地了。

## 四处改动

### 1) 每个模型都能看到真实现场（核心）

新增 `plugin/lib/core/workspace-brief.js`：运行开始时读取工作目录，生成 5~10 行摘要注入 `promptRequest`：

```
【工作区现场（插件自动采集：写计划时以这里的真实路径为准，不要凭空发明目录）】
工作目录: D:/1
顶层目录: pachong/, mmd-ui/, ...
顶层文件: ...
项目文档: pachong/CONTRACT.md → Pachong Contract ｜ ...
提醒: 先读这些目录和文档再写计划；不存在的东西要么自己装、自己起，要么降级继续——不要写「等人工提供」。
```

提案、评审、决策、计划四个阶段看到的都是这段；`state.request` 仍是用户原话（界面不脏）。

### 2) 计划阶段：先勘察、禁止等人工

`PLAN_SYSTEM` 新增：动手前必须读现场文档与配置，**不得凭空发明目录**；**禁止出现「询问用户 / 等人工」的步骤**——缺东西只能 ① 自己找 ② 自己装/自己起 ③ 降级成仍能产出结果的分支，实在无解才在最后一步产出 `blocked.md`。

### 3) 执行阶段：绝不提问、降级继续

`buildExecutorSystem()` 新增：缺东西按「找 → 装/起 → 降级继续」三步走；降级时该步登记失败但 `error` 必须写 `blocked: 缺什么 + 试过什么`，然后继续其它步骤并写 `blocked.md` / `progress.json`；**只要还有成功的步骤，`overall` 填 `partial` 而不是 `failed`**；不要用「需要人工介入」当结束语。
